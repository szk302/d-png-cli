# プロダクト要件定義書 (PRD): `drawio-png-cli`

## 1. 概要 (Overview)

`drawio-png-cli` は、VS Code の draw.io 拡張機能などで扱われる `.drawio.png` 形式のファイルを、AI エージェントと人間がシームレスに相互編集できるようにするための軽量かつ高速な CLI ツールである。

PNG 画像のメタデータ（`zTXt` / `tEXt` チャンク）内に埋め込まれた draw.io の XML データを抽出し、AI による編集後の XML を安全に再埋め込み・画像化するインターフェースを提供する。

---

## 2. 目的・背景 (Background & Goals)

* **課題**: `.drawio.png` 形式はバイナリ（PNG画像）とテキスト（XMLメタデータ）が混在しているため、プログラムや LLM / AI エージェントが直接読み書きを行うことが困難であった。
* **目的**:
1. AI エージェントが安全・確実に draw.io の構造データ（XML）を取り出し、修正・更新できるようにする。
2. 人間が VS Code の GUI で編集した `.drawio.png` と、AI がプログラム経由で作成・更新した構造データを双方向に同期・補完できるようにする。
3. CLI 実行時に XML の構文・基本構造を検証し、不正な入力による上書きを防ぐ。すべての描画・レイアウト不具合の防止は保証しない。



---

## 3. ユースケース (Use Cases)

```
[人間 (VS Code)] ──(GUIで作成)──> filename.drawio.png
                                         │
                                   [drawio-png-cli extract]
                                         │
                                         ▼
[AI エージェント] <──(XML解析・修正)─── diagram.xml
       │
 [drawio-png-cli embed] ──(自動Validation)──> filename.drawio.png
                                         │
[人間 (VS Code)] <──(GUIで微調整)────────┘

```

1. **AI による既存図面の自動アップデート**: 人間が作成した `.drawio.png` から XML を抽出し、AI が図面構造を追加・修正した上で `.drawio.png` へ書き戻す。
2. **AI による新規図面の生成**: AI が一から生成した XML データを `drawio-png-cli embed` に引き渡し、VS Code で即座に開いて人間が微調整できる `.drawio.png` ファイルを出力する。
3. **CI/CD パイプラインでの図面検証**: PR 提出時などに `drawio-png-cli validate` を通すことで、破壊された draw.io ファイルの混入を防ぐ。

## 4. CLI インターフェース仕様 (CLI Specification)

* **コマンド名**: `drawio-png-cli`
* **リポジトリ名**: `drawio-png-cli`

### 4.1. サブコマンド一覧

#### `drawio-png-cli extract`

`.drawio.png` から XML メタデータを抽出し、全ページを非圧縮 XML に展開して出力する。ページ順・名前・属性・未知要素を保持するが、元の文字列表現との完全一致は保証しない。（計画）埋め込み画像をライブラリの画像とハッシュで照合し、一致した画像は既定で編集用の参照に置き換える（[4.2](#42-ライブラリ参照属性計画未実装)）。

| オプション | 型 | 説明 |
| --- | --- | --- |
| `input` (位置引数) | Path | 対象の `.drawio.png` ファイルパス |
| `-o`, `--output` | Path | 出力先 XML ファイルパス（省略時は標準出力 `stdout`） |
| `--keep-images` | Flag | （計画）画像とライブラリの照合・参照への置き換えを行わず、画像データを保持する。[4.2](#42-ライブラリ参照属性計画未実装) を参照 |
| `--raw` | Flag | （計画）PNG に保存された XML を、ページの展開・検証・参照の処理をせずに出力する。[4.2](#42-ライブラリ参照属性計画未実装) を参照 |

* **実行例**:
```bash
# ファイルに出力
drawio-png-cli extract input.drawio.png -o diagram.xml

# パイプラインで標準出力受け取り
drawio-png-cli extract input.drawio.png > diagram.xml

```



---

#### `drawio-png-cli embed`

XML データを `.drawio.png` に挿入・更新する。**実行時に自動でバリデーションを呼び出し、パスした場合のみ書き込む。**

| オプション | 型 | 説明 |
| --- | --- | --- |
| `-i`, `--input` | Path | 入力 XML ファイルパス（省略時は標準入力 `stdin`） |
| `-o`, `--output` | Path | (必須) 出力先 `.drawio.png` ファイルパス |
| `-b`, `--base-image` | Path | ベースとなる既存 PNG ファイルパス。`--no-render` と併用する |
| `--no-render` | Flag | 画像の再描画を行わず、メタデータ（XML）のみを更新する(このオプションを未指定かつ外部レンダラーが存在しない場合、警告終了ではなくエラー終了させる) |
| `--no-validate` | Flag | （デバッグ用）自動バリデーションをスキップして強制書き込みする |

`--no-render` でベース画像を省略した場合は透明な 1×1 PNG を生成する。既存の出力先はベースとして再利用しない。画像と XML が同期されない旨を stderr に警告する。複数ページはすべて保持し、通常の描画では先頭ページを画像化する。

`--no-validate` は XML 検証と正規化を省略するが、UTF-8・サイズ制限・PNG 検査・アトミック保存は省略しない。

* **実行例**:
```bash
# XMLファイルから埋め込み
drawio-png-cli embed -i modified.xml -o output.drawio.png

# stdin 経由でパイプライン結合
cat modified.xml | drawio-png-cli embed -o output.drawio.png

```



---

#### `drawio-png-cli validate`

指定した XML または `.drawio.png` ファイルが正当な draw.io 構造を持っているか事前検証する。

* **実行例**:
```bash
drawio-png-cli validate diagram.xml
drawio-png-cli validate output.drawio.png

```

### 4.2. ライブラリ参照属性（計画・未実装）

#### 背景

AI エージェントは図面を XML で丸ごと書くため、1 図形ずつ座標を指定して挿入する `drawio-png-cli insert` は作業の流れに合わない。一方、画像を埋め込んだエントリー（Simple Icons 等）は style に大きな Base64 を含み、エージェントが書き写せない。また一度挿入すると、`extract` のたびに Base64 が XML に現れ、エージェントのコンテキストを圧迫する。

そこで、エージェントは一覧・検索で取得した画像ハッシュを XML に書き、`embed` が利用者ライブラリから同じ画像を展開する。画像の新規配置と、`extract` で参照にした画像の復元には共通の形式を使う。組み込み図形や複数セルなどのエントリーはライブラリ名・タイトル・必要な番号で指定し、`insert` と同じくセル群を展開する。

参照の方式は、展開する対象に応じて選ぶ。

| 方式 | 主な用途 | `embed` が展開するもの |
| --- | --- | --- |
| エントリーの展開（名前指定） | 組み込み図形・接続線・複数セルの追加。画像を含むエントリーの style やラベルも取り込みたい場合 | プレースホルダーをエントリーのセル群に置き換える |
| 画像の展開（ハッシュ指定） | 利用者ライブラリの画像の新規配置・抽出後の復元 | 入力セルの `image=drawio-png` を同じハッシュの実画像に置き換える |

どちらも通常の `embed` では参照属性を取り除き、展開済みの図面を保存する。次の `extract` で作り直すのは実画像に対するハッシュ指定の参照だけで、セル群から名前指定の参照を復元することはない。

**保存済みの図面では画像データを正とする。** 通常の `embed` は実画像を PNG 内の XML に保存し、`drawioPng*` の参照属性とハッシュは残さない。`extract` は図面の実画像と利用者ライブラリの画像をハッシュで照合し、一致したものだけを編集用の参照と短い印に置き換える。次の `embed` は利用可能な利用者ライブラリから同じハッシュの画像を探して復元し、一時的な参照属性を取り除く。ライブラリのファイル名・タイトル・番号が変わっても、同じ画像が見つかれば復元できる。draw.io で人が差し替えた画像も、次の `extract` ではその画像自体から照合する。

| 段階 | `image` の値 | `drawioPng*` |
| --- | --- | --- |
| PNG に保存した XML | 実画像の `data:` 値 | なし |
| エージェントが新しく書く画像の参照 | 固定の印 `drawio-png` | 一覧・検索から取得した画像ハッシュ。ライブラリ名・タイトル・番号は任意 |
| 通常の `extract` 後（一致あり） | 固定の印 `drawio-png` | 復元キーとなるハッシュと、説明・検索の手がかりとなるライブラリ名・タイトル・必要な番号 |
| 通常の `extract` 後（一致なし） | 実画像の `data:` 値 | 既存のものも除去する |
| `extract --keep-images` 後 | 実画像の `data:` 値 | 保存されていたものを保持し、追加しない |
| 次の `embed` 後 | 元と同じ実画像の `data:` 値（明示的に編集した場合は編集後の画像） | 除去する |

`embed --no-validate` は参照の処理自体を省くデバッグ用の例外であり、入力の参照属性や印をそのまま保存する。

#### 画像の照合に使うエントリー

利用者ライブラリのエントリーを XML にしたもの（`data` のエントリーは `insert` と同じく `shape=image;…;image=…` のセルにする）で、一覧・検索でハッシュを出す対象と、`extract`・`embed` の照合候補を決める。PNG・JPEG 等のラスター画像と、`data:image/svg+xml,…` の SVG を含む。基盤セルとレイヤーはセル数に含めない。組み込みライブラリはハッシュによる配置・逆引き・復元の対象にせず、ライブラリ名・タイトル・必要な番号で新規追加する方式を維持する。

| 分類 | 条件 | 扱い |
| --- | --- | --- |
| 画像のエントリー | 単一のセルで、style の `image` キー（`=` のあるもの。名前付きスタイルの `image` ではない）の値が `data:` で始まる。`<object>`・`<UserObject>` で包まれた単一セルも含む | 画像のハッシュを照合候補にする |
| その他のエントリー | 上記以外（埋め込み画像のない図形・接続線、`image=img/lib/…` のようなパスの画像、複数セル） | 照合候補にしない |

Simple Icons（3,464 エントリー）は、すべて `xml` の単一セルで `image=data:image/svg+xml,…` を持つため、画像のエントリーになる。現在の組み込みライブラリには `data:` を含むエントリーはない。

#### 属性

参照属性は編集用 XML の一時情報とする。画像をハッシュで指定する参照と、エントリーを名前で指定する参照では、必須の属性を分ける。画像の参照は、新規配置と既存画像の復元で同じ形式とする。

| 属性 | 内容 | エントリーを名前で指定 | 画像をハッシュで指定（新規配置・復元） |
| --- | --- | --- | --- |
| `drawioPngLibrary` | ライブラリ名 | 必須 | 任意の手がかり。`extract` は照合結果を書き、エージェントの新規配置では省略できる |
| `drawioPngEntry` | エントリーの正確なタイトル | 必須 | 任意の手がかり。`extract` は照合結果を書き、エージェントの新規配置では省略できる |
| `drawioPngIndex` | ライブラリ内の番号（1 から） | タイトルの重複・空のときに指定する | 任意の手がかり。`extract` が必要に応じて書く |
| `drawioPngHash` | 実画像のハッシュ（`sha256:<小文字の16進数64桁>`） | 付けない | 必須。新規配置は一覧・検索の `imageHash` をそのまま写し、復元用の参照は `extract` が計算して書く |

* `drawioPng` で始まる属性を 1 つでも持つセルを参照とみなす。`drawioPngHash` がなければエントリーを名前で指定する参照、あれば利用者ライブラリの画像をハッシュで指定する参照として扱う。不正な形式のハッシュを名前による参照として扱うことはない。
* `embed`（`--no-validate` を除く）と `validate` は、名前による参照で `drawioPngLibrary`・`drawioPngEntry` のどちらかが欠けていればエラーにする。ハッシュによる画像の参照では、この 2 属性や `drawioPngIndex` がなくても、正しい形式の `drawioPngHash` と `image=drawio-png` があれば処理できる。ハッシュや印がない場合の扱いは下記の状態表に従う。
* style の `image` の値 `drawio-png` は、ハッシュから画像を展開するための予約値とする。ハッシュは `drawioPngHash` の 1 か所だけに書き、印には含めない。参照属性がなくても、この印があるセルは `embed`・`validate` で検査する。
* 参照の属性は 1 つの要素にまとめて書く。`<mxCell>` か、セルを包む `<object>`・`<UserObject>` のどちらでもよい。複数の要素に分かれている場合も、`embed`（`--no-validate` を除く）と `validate` でエラーにする。
* `extract` は、参照属性の欠落や不正を理由にエラーにしない。通常の `extract` では、実画像（`image=data:…`）を持つセルの既存の `drawioPng*` を除去し、画像の照合結果から必要な参照だけを作り直す。実画像を持たないセルの参照属性や印は、そのまま出力して修正できるようにする。`extract --keep-images`・`extract --raw` は既存の参照属性も変更せず、参照属性の検査によるエラーにもせず出力する。各コマンドの処理は「既存のコマンド・オプションとの関係」を参照。
* `extract` が生成する参照属性は、セルが `<object>`・`<UserObject>` で包まれていればその要素に、包まれていなければ `<mxCell>` にまとめて書く。参照のために新しいラッパーは作らない。通常の `embed` は参照を処理した後にこれらの属性を取り除く。ハッシュ指定では既存のラッパー・ID・ラベル・利用者のデータを保持し、名前指定では下記の「エントリーの展開（名前指定）」の ID・上書き・独自データの規則に従う。
* 参照属性を style の外に置くことで、エージェントは参照先を保ったまま図形の style を編集できる。参照属性にはセル固有の情報（ID 等）を入れない。

#### 名前で指定するエントリーの解決

この節は `drawioPngHash` を持たない参照に適用する。利用者ライブラリと組み込みライブラリで共通とし、画像のハッシュによる新規配置・復元は次節の規則に従う。画像を含むエントリーの style やラベルを丸ごと展開したい場合も、名前による参照を使える。

1 つの文字列にまとめないのは、ライブラリ名が `/` を含み（`drawio/aws4-compute`）、タイトルも `/`・`#` を含む・空・重複することがあるため。組み込みライブラリ（12,671 エントリー）では、同じライブラリ内のタイトルの重複が 700 組（1,806 エントリー、145 ライブラリ）、空のタイトルが 71、`/` か `#` を含むタイトルが 152 あり、1,421 のタイトルが複数のライブラリにある（`Lambda` は `drawio/aws3-compute`・`drawio/aws3d`・`drawio/aws4-compute`）。

* `drawioPngLibrary` は `--library` と同じ名前の規則で解決する。省略は許さない（利用者のライブラリを先に探す解決順により、`DRAWIO_PNG_LIBRARY_PATH` の設定で別のエントリーになるのを避けるため）。
* `drawioPngEntry` は `--name` と同じく、完全一致、なければ大文字小文字を区別しない一意の一致で選ぶ。draw.io による数値の変換（`007` → `7`）を戻すための別名の一致は認めない（同じライブラリに `007` と `7` があると、別のエントリーを選んでしまうため）。通常の流れでは保存前に参照属性を取り除くため、参照は draw.io を通らない。`--no-validate` で保存した場合などに `<mxCell>` の参照を draw.io で保存すると、数値に見えるタイトル（`mxUtils.isNumeric` が真のもの）は変換され、解決できずにエラーになることがある。
* 空のタイトルは `drawioPngEntry=""` と書き、`drawioPngIndex` を必須とする。
* `drawioPngIndex` を指定した場合は、その番号のエントリーを選び、そのタイトルが `drawioPngEntry` と上記の規則で一致することを確かめる（ライブラリの更新で番号がずれたことを検出するため）。番号だけでの指定は許さない。照合時に空白を削ったり、改行・タブを空白に置き換えたりしない。正確なタイトルは `library search --json` で取得する（下記）。
* 次の場合は参照を解決できないものとする。ライブラリ・エントリーが見つからない。同名の利用者ライブラリが複数ありライブラリが一意に決まらない。タイトルが一意に決まらず `drawioPngIndex` がない（候補の番号を示す）。番号が範囲外、または番号のエントリーのタイトルが一致しない。`drawioPngIndex` が正の整数でない。
* 名前による参照では、`embed` は参照されたライブラリだけを読む。利用者のライブラリ名は `/` を含まないため、`drawio/` で始まる名前は `DRAWIO_PNG_LIBRARY_PATH` を読まずに組み込みライブラリから解決する。実画像を持つ普通の図面の `embed` はライブラリを読まない。

#### ハッシュで指定する画像の解決

* 新規配置・復元ともに解決のキーは `drawioPngHash` とする。PNG・JPEG・SVG 等の画像データを対象に、`DRAWIO_PNG_LIBRARY_PATH` から利用できるすべての利用者ライブラリを横断して同じハッシュの画像を探す。組み込みライブラリは検索しない。
* `drawioPngLibrary`・`drawioPngEntry`・`drawioPngIndex` は説明と検索の手がかりとして使う。指定されたエントリーを先に調べてもよいが、画像のハッシュが一致した場合だけ採用する。名前が見つからない、タイトルが変わった、番号が範囲外になった、候補のハッシュが異なる場合も、それだけでは復元エラーにせず、他の利用者ライブラリ・エントリーを探す。これらの属性が欠けている場合は最初からハッシュで検索する。
* `extract` は手がかりとして、照合したライブラリの正式な名前とエントリーの正確なタイトルを出力し、タイトルの重複・空の場合は元のライブラリ内の番号も出力する。番号を含め、これらの値の一致は復元の必須条件にしない。属性がある場合の番号の書式（正の整数）は検査する。
* 同じハッシュの画像が複数見つかった場合は、画像だけを取り出すため、いずれを使ってもよい。結果を安定させるため、手がかりの候補で一致しなければ `library search` と同じライブラリ順・エントリー順で最初の一致を使う。同名ライブラリや重複タイトルがあってもハッシュで解決できる。候補の style・ラベル・サイズはコピーしない。
* 例: `icons.xml` を `brands.xml` に変えても、同じ画像が新しいファイルから読み込めれば復元できる。ライブラリのディレクトリをパスに設定していれば、その中のファイル名変更に対応できる。ファイルを直接指定している場合は、`DRAWIO_PNG_LIBRARY_PATH` も新しいパスに更新する必要がある。

#### 参照先と配置情報の取得（`library search`・`--json`）

参照を入れる版で `library search` の結果に画像ハッシュを追加し、`--json` も追加する。エージェントはタイトルで候補を探し、用途に応じて `imageHash` による画像の展開か、正確な名前・タイトル・番号によるエントリーの展開を選ぶ。名前指定のプレースホルダーは、検索結果の配置情報に従って書く。

* 検索語を省略した `library search` は、検索対象の全エントリーをハッシュ付きで一覧表示する。特定のライブラリのアイコン一覧は `library search --library <名前>` で取得する。`library list`・`library ls` は従来どおりライブラリ自体の一覧とする。
* `--json` は `stdout` に JSON 配列を 1 つ出力する。各要素は `library`（正式なライブラリ名）、`index`（1 からの番号）、`title`（元のタイトル）、`width`・`height`（数値のサイズ）、`imageHash` と、下記の配置情報を持つ。該当なしは `[]` とする。style や画像データは含めず、診断は `stderr` に出す。
* `imageHash` は、上記の「画像の照合に使うエントリー」に該当する画像の `sha256:<小文字の16進数64桁>` とする。`extract`・`embed` と同じ計算規則を使い、省略・短縮しない。組み込みライブラリや複数セルなど、対象外のエントリーは `null` とする。同じ画像を持つエントリーには同じ値を出し、エントリーをまとめて省略しない。対象候補でも壊れた XML などで画像を取り出せない場合は `null` とし、`stderr` に警告する。
* `width`・`height` はそのエントリーのサイズを示し、新規配置時の参考に使う。名前指定でサイズを上書きできるかは `canResize` で判断し、`false` の場合はプレースホルダーの幅・高さを省略する。ハッシュ指定はエントリーを置き換えず画像だけを展開するため、配置先の幅・高さを指定する。サイズ・位置・ID・ラベル・画像以外の style・ライブラリ名・タイトル・番号はハッシュに含めない。ハッシュはエントリー全体の識別子ではない。
* `--json` の `title` は、改行・タブ・前後の空白・大文字小文字・空文字をそのまま保持する。JSON の文字列として必要なエスケープだけを行い、デコードすると元のタイトルに戻るようにする。
* 検索語、`--library`・`--library-file`・`--no-builtin`、結果の順序は通常の `library search` と同じにする。`--json` を省略した場合は、従来の 1 エントリー 1 行の表示（ライブラリ名・番号・表示用タイトル・サイズ）の末尾に、タブ区切りで完全な画像ハッシュを追加する。`imageHash` が `null` の場合は `-` を表示する。
* `--library-file` で検索したファイルのハッシュを `embed` で使う場合は、そのファイルも `DRAWIO_PNG_LIBRARY_PATH` に加える。検索コマンドの実行だけでは復元用の画像を保存しない。
* JSON から XML の属性を作るときは、文字列をデコードしてから XML 属性値としてエスケープする。`&`・`<`・`"` に加え、改行・タブ・復帰はそれぞれ `&#10;`・`&#9;`・`&#13;` とする。属性値に改行やタブを直接書くと、XML の解析時に空白へ正規化され、元のタイトルと一致しなくなるため。

配置情報は、名前指定で展開するセル群から求める。基盤セルとレイヤーを除外し、`<object>`・`<UserObject>` とその内側の `<mxCell>` は合わせて 1 セルとして数える。最上位のセルは、親がエントリーのレイヤーであるセルを指す。`data` のエントリーは画像セルに変換してから求め、組み込みライブラリも同じ規則で出力する。

| フィールド | 型 | 内容 |
| --- | --- | --- |
| `cellCount` | 整数または `null` | 子セルも含む展開対象のセル数 |
| `topLevelCount` | 整数または `null` | 最上位のセル数。`1` ならプレースホルダーの ID を維持でき、ラベル・style・独自データを上書きできる |
| `kind` | 文字列または `null` | 最上位がすべて図形なら `vertex`、すべて接続線なら `edge`、両方を含むなら `mixed`。グループは子に接続線があっても、最上位が図形なら `vertex` |
| `canResize` | 真偽値または `null` | 名前指定で幅・高さを上書きできるか。`cellCount=1` かつ `kind=vertex` の場合だけ `true`。子セルのあるグループや接続線は `false` |

* `kind=vertex` なら `vertex="1"`、`kind=edge` なら `edge="1"` をプレースホルダーに書く。`mixed` なら両方を省略し、各セルの種類をエントリーから引き継ぐ。`source`・`target` を指定できるのは `cellCount=1` かつ `kind=edge` の場合に限る。
* 壊れた XML・空のセル群・最上位セルがない構造などで配置情報を求められない場合は、4 フィールドをすべて `null` にして `stderr` に警告する。最上位セルの種類が図形・接続線のどちらにも決まらない場合（両方が `1` の場合も含む）も同じ扱いとする。`null` を `0` や `false` として扱わず、エージェントはそのエントリーの名前指定による配置を行わない。ほかの検索結果は出力する。
* これらの情報はプレースホルダーを書くための案内であり、`embed` は実際に読み込んだエントリーから同じ判定を行う。XML に配置情報のフィールドを写す必要はない。通常のテキスト表示の列は増やさず、配置情報が必要な場合は `--json` を使う。

例: タイトルに改行を含むグループ（最上位の図形 1 つと子セル 2 つ）を取得し、名前による参照を書く。`canResize=false` のため幅・高さを省略する（JSON の `\n` は改行を表す）。

```sh
drawio-png-cli library search --library my-lib --json
```

```json
[{"library":"my-lib","index":1,"title":"Group\nB","width":20,"height":20,"imageHash":null,"cellCount":3,"topLevelCount":1,"kind":"vertex","canResize":false}]
```

```xml
<mxCell id="group-b" vertex="1" parent="1"
        drawioPngLibrary="my-lib" drawioPngEntry="Group&#10;B" drawioPngIndex="1">
  <mxGeometry x="40" y="40" as="geometry" />
</mxCell>
```

#### 画像の展開（ハッシュ指定）

画像アイコンは、一覧・検索で得た `imageHash` を `drawioPngHash` に写し、`style` に `shape=image;image=drawio-png;` を持つセルを書く。ID・親セル・位置・幅・高さはエージェントが指定する。新規配置でも既存画像の復元でも、`embed` が補うのは `image` の値だけで、サイズや他の style をライブラリから補完しない。

次は JSON と配置用 XML の形式例（ハッシュ値は例示用）。幅・高さには検索結果の値を使い、位置は図面に合わせて指定する。実際の配置では、利用可能なライブラリの検索結果をそのまま使う。

```json
[{"library":"my-icons","index":1,"title":"Example icon","width":48,"height":48,"imageHash":"sha256:ef32cf9041d7704a17c4ae98ef1e433562ba9098c7bd7f27b99eec8e371f5116","cellCount":1,"topLevelCount":1,"kind":"vertex","canResize":true}]
```

```xml
<mxCell id="icon-1" vertex="1" parent="1"
        drawioPngHash="sha256:ef32cf9041d7704a17c4ae98ef1e433562ba9098c7bd7f27b99eec8e371f5116"
        style="shape=image;image=drawio-png;aspect=fixed;">
  <mxGeometry x="40" y="40" width="48" height="48" as="geometry" />
</mxCell>
```

* `drawioPngLibrary`・`drawioPngEntry`・`drawioPngIndex` は省略できる。検索結果のタイトルはアイコンの選択に使い、配置先のラベルには自動でコピーしない。
* 同じハッシュを複数のセルに使える。位置・サイズ・ラベルを変えてもハッシュは変わらない。
* アイコンを別の検索結果に差し替える場合は、`image=drawio-png` を保ったまま `drawioPngHash` を置き換える。名前・タイトル・番号を手がかりとして残していた場合は、混乱を避けるため取り除くか、新しい検索結果に合わせる。
* 印を実画像の値に置き換える場合、または `image` キーを削除する場合は、その編集を優先する。ハッシュだけを残しても画像を補完しない。下記の状態表に従い、`embed` が不要な参照属性を除去する。
* 同じハッシュの画像を利用可能なライブラリに見つけられなければ、`embed` はエラーにする。タイトルや番号から別画像を選び直すことはしない。

#### エントリーの展開（名前指定）

エージェントは `drawioPngHash` を持たない 1 つのセル（プレースホルダー）を書く。`embed` は、プレースホルダーをエントリーのセル群に置き換える。処理は `insert` と同じで、エントリーの要素・属性（style・ラベル・`<object>` のデータ・接続線のジオメトリ）をそのまま写す。`drawioPngHash` を持つセルは、新規配置か既存画像の復元かによらず画像だけを展開するため、このセル群への置き換えは行わない。

```xml
<!-- エージェントが書く XML -->
<mxCell id="fn" value="Handler" vertex="1" parent="1" drawioPngLibrary="drawio/aws4-compute" drawioPngEntry="Lambda">
  <mxGeometry x="40" y="40" as="geometry" />
</mxCell>
```

* **位置**: セル群の左上をプレースホルダーの `x`・`y`（省略時は 0）に合わせ、`parent` はプレースホルダーのものを引き継ぐ。接続線のエントリーは下記の「接続線のエントリー」に従う。
* **ID**: 最上位のセルが 1 つなら、そのセルにプレースホルダーの ID を付ける。他のセルは `<ID>-<n>` とし、`<n>` はエントリー内の文書順に 1 から振る。最上位のセルが複数のエントリーでは、すべてのセルを `<ID>-<n>` とする。この場合、プレースホルダーの ID を `source`・`target`・`parent` 属性、または接続線の style の `sourcePort`・`targetPort` が参照しているセルがページ内にあれば、`embed` は展開前にエラー終了し、既存出力を変更しない。ページ内の既存 ID と重なればエラーにする。番号の振り方が決まっているため、エージェントは `embed` の前に子のセルやポートへの接続線を書ける。
* **接続**: エントリー内の接続先・親子関係は振り直した ID に対応付ける。図面の接続線がプレースホルダーの ID を指していれば、最上位のセルにつながる。
* **接続線のエントリー**: エントリーが単一の接続線なら、プレースホルダーの `source`・`target` を引き継ぐ。プレースホルダーの `mxGeometry` に点（`sourcePoint`・`targetPoint`・`points`）があれば、エントリーの点の代わりに使う。`source`・`target` も点もなければ、エントリーの点を `x`・`y` に合わせて移動する。例:

  ```xml
  <!-- a と b を drawio/general の Curve でつなぐ -->
  <mxCell id="e" edge="1" parent="1" source="a" target="b"
          drawioPngLibrary="drawio/general" drawioPngEntry="Curve">
    <mxGeometry relative="1" as="geometry" />
  </mxCell>
  ```

* **種類の一致**: プレースホルダーの `edge="1"`・`vertex="1"` がエントリーの最上位のセルの種類と異なる場合、両方が `1` の場合、および単一の接続線でないエントリーのプレースホルダーに `source`・`target` がある場合はエラーにする（接続を黙って失わないため）。最上位に図形と接続線が混在する場合はプレースホルダーの両属性を省略し、エントリーの各セルの種類を保持する。空のセル群・最上位セルがない構造・最上位の種類が決まらないエントリーは展開エラーにする。
* **上書き**（`insert` の `--width`・`--height`・`--label` と同じ制約）:
  * `width`・`height`: 単一の図形のセルに限る。片方だけなら縦横比を維持する。
  * `value`（包まれていれば `label`）: 最上位のセルが 1 つのエントリーに限る。省略時はエントリーのラベルを使う。
  * `style`: 最上位のセルが 1 つのエントリーに限り、キー単位で最上位のセルの style に重ねる（同じキーはプレースホルダーの値を優先する）。`image` も上書きでき、その画像を保存する。名前付きスタイル（`=` のないトークン）を書いた場合はエラーにする。
  * 制約に反する指定はエラーにする。
* **参照の属性**: 画像を含め、展開したセルに残さない。以後は普通のセルで、ライブラリの更新は反映されない。次の `extract` で参照にできるかは、その時点の実画像とライブラリの画像の一致だけで決める。
* 画像を含む複数セルのエントリーもセル群として展開する。次の `extract` では各セルの画像を個別に照合する。照合候補に同じ画像がなければ、そのセルの Base64 は出力に残る。

独自データの引き継ぎは、プレースホルダーとエントリーの最上位セルを包む `<object>`・`<UserObject>` の属性に適用する。ここでいう独自データは `id`・`label` と `drawioPng` で始まる属性を除くもの（例: `owner`・`note`）で、ID・ラベル・参照属性は上記の専用の規則に従う。

* 最上位セルが 1 つなら、エントリー側の独自データにプレースホルダー側の独自データを属性ごとに重ねる。同名の属性はプレースホルダー側を優先し、明示した空文字も上書きとする。指定しなかった属性と子セルの独自データはエントリーのまま保持する。
* 最上位セルが 1 つの場合、ラッパーはプレースホルダーにあればその要素名（`object` または `UserObject`）を使い、なければエントリー側のラッパーを使う。両方にあっても入れ子にはしない。両方になければ `<mxCell>` のままにする。
* この統合で出力をラッパーで包む場合、ID はラッパーの `id` に置き、ラベルは `label` に置く。ラッパーのない入力の `value` はラベルとして扱い、プレースホルダーのラベルがあればそれを、なければエントリーのラベルを使う。内側の `<mxCell>` に ID・ラベルを重複して持たせない。セルの種類・接続・style・ジオメトリは上記の規則で処理する。
* 最上位セルが複数の場合、プレースホルダーが独自データを 1 つでも指定していれば、引き継ぎ先を決められないため展開前にエラーにする。全セルへの複製や黙っての破棄はしない。指定がなければエントリーの各ラッパーと独自データを保持し、プレースホルダーのラッパーは残さない。ラベル・style の上書きも上記の制約どおり拒否する。いずれの展開エラーでも既存出力を変更しない。

例: エントリーの最上位セルに `owner="library" note="keep"`、プレースホルダーに `owner="team" ticket="42"` がある場合、出力は `owner="team" note="keep" ticket="42"` となる。プレースホルダーに `note=""` も指定すれば、出力の `note` は空文字になる。

#### 画像の逆引きと復元

* **ハッシュ**: XML の属性のエスケープを解いた style の `image` キーの値を UTF-8 にしたものの SHA-256。ライブラリの `data` のエントリーは、セルへの変換で `;base64,` を `,` にした後に計算する。`library search`・`extract`・`embed` の図面側とライブラリ側で同じ規則を使う。画像の見た目ではなく `data:` の文字列を照合するため、同じ絵でも SVG の書き方やエンコードが違えば一致せず、`extract` は元画像を保持する。
* **`extract` の対象**: 全ページの、style に `image=data:…` を持つセルを個別に調べる。セルが `<object>`・`<UserObject>` で包まれている場合やグループの子の場合も対象にする。既存の `drawioPng*` の有無・内容にかかわらず、実画像から照合する。`image` が印などで実画像のないセルは、参照属性も印も保持する（復元に必要な情報を失わず、抽出した XML で修正できるようにするため）。
* **既存の参照属性**: 対象セルの `<mxCell>` と、それを包む `<object>`・`<UserObject>` から、`drawioPng` で始まる属性をすべて除去する。古いライブラリ名・タイトル・番号・ハッシュは照合に使わない。一部が欠けていたり、複数要素に分かれていたりしても同じ扱いとする。画像と無関係な利用者のデータは保持する。
* **照合**: 図面側の実画像のハッシュを計算し、利用者ライブラリの画像のハッシュから引いた候補と照合する。一致した場合は、復元キーの `drawioPngHash` と、手がかりの `drawioPngLibrary`・`drawioPngEntry`・必要なら `drawioPngIndex` を新しく付け、`image` の値だけを固定の印 `drawio-png` に置き換える。新規配置と同じ形式であり、印にハッシュを重複して書かない。一致しなければ元画像を保持し、`drawioPng*` のない普通の画像セルとして出力する。ライブラリを利用できず一致を確認できない場合も同じとする。いずれも参照属性と `image` 以外の属性・style・ラベル・ジオメトリは変えない。
* **複数の一致**: `library search` と同じライブラリ順・エントリー順で最初のハッシュ一致を選ぶ。ライブラリ名やタイトルが重複していても候補から除外しない。タイトルの重複・空の場合は番号も出力する。番号は候補内の連番ではなく元のライブラリ内の番号とする。同じ画像を持つエントリーの style やサイズが異なっても、復元するのは画像だけなので図面には影響しない。
* **ライブラリの読み込み**: 通常の `extract` では対象の埋め込み画像がある場合だけ行う。設定された利用者ライブラリの画像エントリーのハッシュを実行中に一度だけ索引化し、同じ画像を持つ複数セルにもこの索引を使う。`embed` のハッシュによる新規配置・画像復元で横断検索が必要な場合も同じ方式で索引を作り、実行中は再利用する。組み込みライブラリは索引に含めない。見つからない・読めないライブラリや壊れたエントリーは警告して候補から除外し、利用できる候補だけで照合を続ける。利用者ライブラリが未設定、または利用できる候補に一致する画像がなければ、`extract` は元画像のまま抽出し、印の展開が必要な `embed` はエラーにする。`extract --keep-images`・`extract --raw` はライブラリを読まない。
* **案内**: 画像を印に置き換えた場合は、stderr に件数と `--keep-images` の案内を 1 行出す。

`embed` は、参照の構造を検査した後、セルの状態に応じて次のとおり扱う。

| セルの状態 | `embed` の処理 |
| --- | --- |
| 参照属性も印もない普通のセル | 実画像を含めそのまま保持する。ライブラリは読まない |
| 参照属性あり、`drawioPngHash` なし、印なし（名前による指定） | 上記の「エントリーの展開（名前指定）」を行い、参照属性を除去する。参照先を解決できなければエラー |
| `drawioPngHash` あり、`image=drawio-png`（新規配置・復元） | 利用可能な利用者ライブラリから同じハッシュの画像を探し、`image` を実画像に置き換えて参照属性を除去する。名前・タイトル・番号の不一致では失敗せず、同じハッシュの画像が見つからなければエラー |
| `drawioPngHash` あり、`image` が印以外の値（エージェントが実画像等を指定した） | 指定された値を保持し、参照属性を除去する。ライブラリは読まない |
| `drawioPngHash` あり、`image` キーがない（エージェントが画像を消した） | 画像がない状態を保持し、参照属性を除去する。ライブラリは読まない |
| `image=drawio-png` があるのに `drawioPngHash` がない、または印の有無によらずハッシュの形式が不正 | エラー。ハッシュが正しい形式なら、ライブラリ名・タイトル・番号の欠落だけではエラーにしない |

* 新規配置・復元ともに `image` の値だけを展開する。入力セルの style の他のキー・ラベル・ジオメトリ・利用者のデータは保持し、エントリーのセルで置き換えない。印を残すことで、ハッシュから画像を展開したいセルとエージェントが画像を削除したセルを区別する。
* 抽出後にライブラリが更新されても、別のエントリーや別の利用者ライブラリに同じハッシュの画像が残っていれば復元する。利用可能な利用者ライブラリのどこにも一致する画像が見つからない場合に、復元時の `embed` が既存出力を変更せずエラー終了し、元の PNG から `--keep-images` で取り出し直すよう案内する。別の画像への自動置換は行わない。ライブラリの更新後に初めて `extract` する場合は、一致する候補がなければ元画像を保持し、既存の `drawioPng*` を除去するため、そのまま編集・保存できる。

#### 既存のコマンド・オプションとの関係

* **`embed`**: `--no-render` を含め、ページを展開した後、まず下記の `validate` と同じ参照の検査を行う。その後に参照を展開し、展開後の図面を検証する。参照の検査または展開に失敗した場合は既存出力を変更せずエラー終了する。`--default-font` は参照の展開の後に適用する（エントリーの style にある `fontFamily` は、既存の明示指定として保持される）。
* **`embed --no-validate`**: 参照を処理しない（XML の解析を省くデバッグ用のため）。プレースホルダーや印はそのまま保存される。
* **`validate`**: ライブラリを読まずにできる参照の検査を行う。名前による参照では `drawioPngLibrary`・`drawioPngEntry` の欠落をエラーにする。ハッシュによる画像の新規配置・復元ではこれらの属性と番号を任意とし、名前・タイトルの変更や番号の範囲外は検査しない。両方に共通して、指定されている `drawioPngIndex` が正の整数でない場合、複数の要素に分かれた属性、不正な形式の `drawioPngHash`、`drawioPngHash` のない `image=drawio-png` をエラーにする。ライブラリ・エントリーの存在や、ライブラリ画像のハッシュは検査しない。
* **`extract`**: 参照の不備ではエラー終了しない。既定の出力では「画像の逆引きと復元」に従い、実画像を持つセルの古い参照属性を除去してライブラリと照合し、一致したものだけに新しい参照属性と印を付ける。実画像を持たないセルの参照属性や印は保持する。`--keep-images`・`--raw` はライブラリの読み込み・照合・参照属性の追加や除去・印への置き換えを行わない。PNG の検査や、通常の `extract` の XML 解析・ページ展開でのエラーは従来どおりとする。単体で draw.io で開ける XML が必要な場合は `--keep-images` を使う。

#### `extract` のオプション

| オプション | ページ | 画像（`image=data:…`） | 用途 |
| --- | --- | --- | --- |
| なし | 非圧縮に展開する | 実画像から参照を作り直す。一致すれば印に置き換え、不一致なら元画像を保持して古い参照属性を除去する | エージェントの通常の編集 |
| `--keep-images` | 非圧縮に展開する | 残す（参照の属性も変更しない。従来の `extract` と同じ出力） | ライブラリがない環境での編集・保存、単体で開ける XML |
| `--raw` | 保存されたまま | 残す | 診断、PNG の内容の確認 |

* `--raw` は、PNG のチャンクから図面のメタデータを復号（`zTXt` の展開、旧 raw DEFLATE の展開、URL エンコードの解除）した XML をそのまま出力する。ページの展開・XML の検証・参照の処理は行わない（壊れた図面の診断にも使えるようにするため）。チャンクの検査と、競合するメタデータの拒否は従来どおり行う。drawio-png-cli の `embed` はページを展開して保存するため、圧縮されたページが出力されるのは draw.io で保存した場合である。
* `--raw` と `--keep-images` の併用は引数エラー（終了コード `2`）にする。
* `embed` は圧縮ページを展開してから参照を処理するため、どのオプションで取り出した XML も `embed` に渡せる。

#### `insert` の扱い

参照で `insert` の機能（画像・図形・複数セルのエントリーの挿入、ID の振り直し、エントリーの要素の写し、サイズ・ラベルの指定）を代替する。代替の仕方が異なる点:

* `insert` は新しい ID を出力する。参照では、ID の振り方（上記）が決まっているため、`embed` の前に分かる。
* `insert --library-file` に相当するものはない。そのファイルを `DRAWIO_PNG_LIBRARY_PATH` に加える。`--no-builtin` は、ハッシュによる画像の指定では利用者ライブラリだけを探し、名前による参照では `drawioPngLibrary` でライブラリを必ず指定するため不要。
* `insert` は XML だけを書くが、`embed` は PNG を書く。描画が不要なら `embed --no-render` を使う。

時期: 参照を入れる版で `insert` の実行時に非推奨の警告を出し、その次のマイナー版で削除する。現在の `Cargo.toml` は `0.1.0` で、次の版には互換性のないコマンド名の変更（`dip` → `drawio-png-cli`）が既に入っているため、参照を入れる版を 0.2.0 とし、削除は 0.3.0 とする。削除にあわせて、`insert` を案内している次の箇所を変更する: `library style` のエラーメッセージ（`src/main.rs`）、README、スキル（`assets/skill/drawio-png.md`・`drawio-png-full.md`）。

#### `library style` とスキルの案内

* `library style` は残す。参照の属性を使わず draw.io の通常の XML だけで描く場合や、上書きしたいキー（色など）を調べる場合に使う。v0.1.0 の公開後に追加したもので、未公開。
* スキルの基本の手順（`drawio-png-cli skill`）では、図形・アイコンの追加は参照の属性を使う手順で案内し、`library style` の手順は載せない。保存済みの実画像を正とし、編集用の参照とハッシュは `embed` で除去すること、画像データを省略せず取り出すには `--keep-images` を使うことも案内する。画像の新規配置と抽出後の復元で同じハッシュ・印の形式を使い、ライブラリ名・タイトル・番号は任意の手がかりであることを説明する。
* 新規追加の候補は `library search --json` で調べる。検索語を省略すれば一覧になり、検索語を指定すれば候補を絞り込めることを案内する。画像だけを追加する場合は `imageHash` を `drawioPngHash` に写して `shape=image;image=drawio-png;` と位置・幅・高さを書く。ハッシュをエージェント自身で計算・推測・短縮する手順にはしない。エントリーの style・ラベル・独自データも取り込みたい場合は、`imageHash` があっても名前指定を選べることを案内する。
* 組み込み図形・複数セルなどを名前指定で追加する場合は、正確な `library`・`title` と必要な `index` から参照を作る。`kind` に応じてセルの種類を指定し、`canResize=false` なら幅・高さを省略する。`topLevelCount` からラベル・style・独自データの上書き可否を判断する。配置情報が `null` のエントリーは名前指定で配置しない。改行・タブ・復帰を XML の文字参照にする方法も含める。
* `library style` の使い方は別の文書に分け、基本の手順からは「style のキーを調べる場合は読む」とだけ案内する。文書は版と一致させるため、`skills/drawio-png/` に置かず、`drawio-png-cli skill` と同じく CLI に同梱して出力する。

#### draw.io での保持の確認（参考）

以下は参照属性を PNG に残す案を検討した際の確認記録である。現在の仕様では通常の `embed` が参照属性を取り除くため、draw.io による属性の保持には依存しない。

`<mxCell>` と `<object>` に独自の属性を付けた `.drawio.png` を、VS Code 拡張（draw.io 26.0.2）と draw.io Desktop 31.4.5（Linux arm64）で編集・保存し、`extract` で確認した（2026-10-11）。VS Code は手作業、Desktop は DevTools Protocol から draw.io の操作（`labelChanged`・`moveCells`・`copy`／`paste`・`duplicate`・`setStyle`・`setCellStyles`・`setAttributeForCell`）を呼び、保存（`save` アクション）した。レビュー（2026-10-11）で、draw.io 26.0.2 の Web 資材を使い codec と `Graph` の API でも確かめた。

| 操作 | VS Code 拡張 | Desktop |
| --- | --- | --- |
| 開いて保存（無関係な図形を追加） | 保持 | 保持 |
| ラベルの変更 | 保持 | 保持 |
| 移動（接続線を含む） | 保持 | 保持 |
| コピー＆ペースト | 新しいセルにも複製 | 新しいセルにも複製 |
| 複製（`duplicate`） | 新しいセルにも複製（API で確認） | 新しいセルにも複製 |
| スタイルの編集（style 全体の変更・キー単位の変更） | 保持 | 保持 |
| スタイルの貼り付け | style の独自のキーは写らない（`Graph.cellStyles` のキーだけを貼り付けるため。API で確認） | 未確認 |
| データを編集（`setAttributeForCell`） | セルが `<UserObject>` で包まれ、`<mxCell>` の属性は中の `<mxCell>` に残る（API で確認） | 同左 |

* `;`・`=`・日本語・`&`・`"`・`true`・空文字を含む値は、そのまま保持された。
* `<mxCell>` の属性のうち、数値に見える値は数値として読み込まれ、正規の表記で書き戻される（`007` → `7`、`1.50` → `1.5`、`1e3` → `1000`、` 42` → `42`）。`mxObjectCodec.isNumericAttribute` が `mxUtils.isNumeric` で判定し、`mxCellCodec` が除外するのは `value` だけのため。`<object>` の属性は変換されない。
* 保持されるのは、draw.io の `mxObjectCodec` が未知の XML 属性をセルのプロパティとして読み込み、保存時にすべてのプロパティを属性として書き出すことによる（`decodeAttribute`・`encodeObject`）。`<mxCell>` の属性は公式の独自データの置き場所ではないため、将来の draw.io で変わる可能性がある。`embed --no-validate` で参照を残した場合は、この変換や保持の制約を受ける。

## 5. 自動バリデーション仕様 (Validation Rules)

ファイル破損を防ぐため、`drawio-png-cli embed` 実行時および `drawio-png-cli validate` 呼び出し時には以下の **3段階の検証** を直列で実施する。いずれかの段階でエラーが発生した場合、処理を即座に中断し、終了コード `1` とエラー内容を出力する。

```
[入力 XML/stdin]
       │
       ▼
1. XML Syntax Check (Well-formed)
       │ Pass
       ▼
2. Root Tag Check (<mxfile> / <mxGraphModel>)
       │ Pass
       ▼
3. Essential Cell Check (id="0" & id="1")
       │ Pass
       ▼
 [処理継続 (embed / exit 0)]

```

1. **XML 構文チェック (Well-formed Check)**:
* タグの対構造、エスケープ漏れ、文字コードが正常な XML であるか。


2. **ルート要素チェック (Root Tag Check)**:
* ルート要素が `<mxfile>` または `<mxGraphModel>` であるか。


3. **基盤セル存在チェック (Essential Cell Check)**:
* 各ページの `<mxGraphModel><root>` 直下にデフォルトセル（`id="0"` および `id="1"` の `<mxCell>`）が存在するか。圧縮ページは展開して検証し、空の `<mxfile>` や復号不能なページは拒否する。

## 6. レンダリング戦略

draw.io Desktop 27.0.2 以降と Chromium / Chrome のヘッドレス描画に対応する。Desktopの先頭ページは 1-based の `--page-index 1`、Web描画APIは `from: 0, to: 0` で指定する。

* Desktop の検索順: `DRAWIO_PNG_DRAWIO_PATH` → PATH の `drawio` / `draw.io` → OS 標準インストール先。
* `DRAWIO_PNG_DRAWIO_PATH` の明示指定が不正な場合はエラーとし、別の候補には切り替えない。
* `DRAWIO_PNG_DRAWIO_ARGS` で Desktop の追加オプションを指定できる。`DRAWIO_PNG_DRAWIO_PATH` は実行ファイルのパスのみを受け付ける。
* `DRAWIO_PNG_DRAWIO_ARGS` は全 OS 共通の POSIX シェル形式で引用符・バックスラッシュを処理して引数へ分割する。シェル実行、環境変数展開、コマンド置換、ホームディレクトリ展開、glob 展開は行わない。
* 未設定・空文字・空白のみは追加引数なし。閉じていない引用符または Unicode として読めない環境変数は Desktop 起動前に終了コード `1` でエラーにし、既存出力を維持する。
* 追加引数は `drawio-png-cli` が生成する描画引数の前に渡す。入力ファイル・出力先・形式・ページ選択は `drawio-png-cli` が管理し、これらを変更する追加オプションや `--` の指定はサポートしない。
* `extract`・`validate`・`embed --no-render` は `DRAWIO_PNG_DRAWIO_ARGS` を読み取らない。
* 一時ファイルへ先頭ページを描画し、全ページの XML は `drawio-png-cli` が PNG に埋め込む。
* 描画は 60 秒でタイムアウトする。選択可能なレンダラーがない場合・描画失敗時はエラー終了する。
* `--no-render` では Desktop を検索・起動せず、ベース画像または新規透明 PNG にメタデータを保存する。
* Linux のディスプレイがない環境では利用者が Xvfb 等を用意する。`drawio-png-cli` は sandbox を自動無効化しない。
* `embed --renderer auto|desktop|chromium` を提供し、既定は `auto`。Desktopが見つからないときだけChromiumへ切り替え、明示指定の不正や描画失敗では切り替えない。
* Chromiumの検索順は `DRAWIO_PNG_CHROME_PATH` → `CHROME_PATH` → PATH → OS標準パス。PATH・OS標準パスでは Chrome を Chromium より優先する。`DRAWIO_PNG_CHROME_ARGS` はPOSIX形式で分割し、シェルを起動しない。
* Chromiumは基本描画資材をバイナリに同梱し、`DRAWIO_PNG_DRAWIO_WEB_PATH` で `export3.html` を含むローカルWeb資材を指定できる。不正指定ではエラーとし、資材の自動取得はしない。
* 同梱対象は基本図形・接続線・日本語・HTMLラベル・埋め込み画像。追加アイコン・ステンシル、数式・Mermaid・自動レイアウト資材は除外。必要資材が欠ける図面や未知の図形ではエラーにする。
* 外部HTTP(S)画像・フォント等の取得は既定で禁止。Chromium専用の `--allow-network` で許可できる。`--renderer` / `--allow-network` と `--no-render` は引数エラー。
* RustからCDPで専用プロファイルのChromiumを制御し、ループバックの資材サーバーを使用する。起動からPNG取得まで60秒。タイムアウト・失敗時もブラウザーとサーバーを片付け、既存出力を維持する。
* Chromiumは `--chromium-mode raw|desktop|vscode` で出力方式を選ぶ。CLI指定 → `DRAWIO_PNG_CHROMIUM_MODE` → `vscode`（SVG→Canvas、XMLのscale・border反映）の順に選ぶ。環境変数はChromium選択時だけ参照し、CLI指定があれば無視する。`raw` はDPR 1のキャプチャを画素加工せず使用し、`desktop` はDPR 2のキャプチャをHamming1で半分に縮小する。全モードで全ページXMLを埋め込む。モード指定はno-render・Desktop選択時には拒否する。取得画像・中間SVG／CanvasはRGBAで64 MiB以下に制限し、60秒の描画期限を維持する。詳細は [描画互換性](rendering.md) に記載する。
* 資材のライセンス・出典・ハッシュを記録する。`drawio-png-cli licenses` で同梱資材の表示・全文を取得可能とする。
* `embed --default-font FAMILY` と繰り返し指定可能な `--fallback-font FAMILY` により、両レンダラーへ渡すセルのフォント候補を統一できる。既存の明示指定を優先し、設定を全ページの埋め込みXMLにも保存する。省略時は従来の動作を保持し、特定の日本語フォントを強制しない。適用範囲と互換性は [フォント指定の仕様](fonts.md) に従う。

コンテナでの指定例（Desktop・Xvfb・xauth のインストールが必要）:

```sh
export DRAWIO_PNG_DRAWIO_PATH=/opt/drawio/drawio
export DRAWIO_PNG_DRAWIO_ARGS='--disable-gpu --disable-dev-shm-usage'
xvfb-run -a drawio-png-cli embed -i diagram.xml -o diagram.drawio.png
```

追加オプションは仮想ディスプレイを起動しない。Xvfb を `drawio-png-cli` の外側で起動するか、`DRAWIO_PNG_DRAWIO_PATH` に `"$@"` を転送するラッパーを指定する。

## 7. 非機能要件 & 技術スタック (Non-functional Requirements)

### 7.1. 非機能要件

* **高速起動**: AI エージェントのツール呼び出しループを阻害しないため、リリースビルドの起動と小規模入力の処理を数十ミリ秒以下の目標で測定する。外部レンダラーの起動・描画時間は別途評価する。
* **ポータビリティ**: 外部依存（Node.js や Python ランタイム等）を持たない単一バイナリ（Single Binary）として配布可能であること。
* **アトミック書き込み**: 出力先と同じディレクトリの一時ファイルに保存・同期後、アトミックに置換する。検証・描画・保存失敗時は既存出力を維持する。

### 7.2. 技術スタック (Rust)

* **言語**: Rust
* **使用クレート**:
* `clap`: CLI 引数・サブコマンドの構文解析
* `png`: PNG 画像の検査と透明画像の生成。メタデータはチャンク単位で直接置換し、`crc32fast` で CRC を検証・生成する
* `flate2`: draw.io データの Deflate 圧縮・解凍
* `base64`, `urlencoding`: メタデータのエンコード・デコード処理
* `roxmltree`: XML の検証とソース範囲に基づくページ展開。全体の再シリアライズを避け、未知要素や属性を保持する
* `tempfile`: 同一ディレクトリでのアトミック保存と描画用一時ファイル
* `shell-words`: `DRAWIO_PNG_DRAWIO_ARGS` の引用符・エスケープを含む引数分割

---

### 7.3. 入出力の制約

* UTF-8 XML（BOM 可）を扱い、DTD・外部エンティティは拒否する。
* 入力・展開データ・出力 PNG・デコード後の画像バッファはそれぞれ 64 MiB を上限とする。
* PNG シグネチャ、チャンク境界、CRC、画像データを検査する。
* `tEXt` / `zTXt` の `mxfile` / `mxGraphModel` を読み取る。旧 raw DEFLATE と二重 URL エンコードにも対応する。
* 競合する図面メタデータはエラー。同一内容の重複は許容する。書き込み時は図面メタデータを一つに統一する。
* 成功 `0`、処理・検証エラー `1`、引数エラー `2`。診断・警告は stderr に出力する。

* **Diff サブコマンド (`drawio-png-cli diff`)**: 2つの `.drawio.png` の XML 構造差分（追加・削除された図形やテキスト）をテキストベースで出力する機能。
